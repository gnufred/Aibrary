# Editorial guidance for technical tutorials

- State who the chapter is for and what problem it addresses. For a continuing example, recall the state the reader should have reached and point to its setup. Learning Git opens a later chapter by reconnecting earlier concepts to the next operation and showing the state the reader needs. [Learning Git, chapter 3](https://www.oreilly.com/library/view/learning-git/9781098133900/lg_ch03.xhtml)
- Turn the opening promise into an early, observable result. Put the minimum setup before the first example and keep optional tools and alternate environments out of that path. Learning Go's opening chapter previews setup, verification, and a small program before the broader tooling discussion. [Learning Go, 2nd Edition, chapter 1](https://www.oreilly.com/library/view/learning-go-2nd/9781098139285/ch01.html)
- Give a subchapter one question to answer. Define related terms together when the reader needs to distinguish them, then build examples around one meaningful change at a time. Put specialized variants after the reader can explain the common case. The modules chapter of Learning Go introduces its organizing concepts before the later sections on dependency and publishing workflows. [Learning Go, 2nd Edition, chapter 10](https://www.oreilly.com/library/view/learning-go-2nd/9781098139285/ch10.html)
- Set the depth and version expectations early. Give foundational topics room to develop and use recap questions or short exercises where they reinforce a chapter's goal. Learning Python states its audience and version scope in the preface, separates advanced topics in the outline, and places knowledge checks throughout. [Learning Python, 6th Edition, preface and contents](https://www.oreilly.com/library/view/learning-python-6th/9781098171292/preface01.html)
